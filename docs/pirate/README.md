# Pirate design

The Android game and browser editor share the OBJ parts and surface textures in `assets/pirate`. The redesign follows the supplied pirate reference: red skull barrels, wooden crates, brass treasure chests, glazed anchor bottles, tied coin sacks, powder kegs, timber platforms, a brass-banded cannon, sunset harbor scenery, and timber/brass/teal controls.

Cargo, cannon, and platforms are real 3D meshes. Bands, rivets, skulls, braces, locks, bottle anchors, rope ties, and coin stacks are modeled geometry. The sky, distant ship, lighthouse, palms, and peripheral lanterns are illustrated. A separate 3D water mesh renders in front of the harbor plate, with a mask defining the visible sea around the shoreline, ship, and dock.

## Assets and gameplay

`assets/objects/manifest.txt` maps the existing numeric target types to pirate meshes. `assets/pirate/catalog.json` lists the model parts. Each part has its own texture and material finish. Brass and iron are metallic, bottles have a glossy clear coat, and cloth has a rough finish. These defaults are matched in Rust and Filament Web. Existing material overrides still apply.

Level JSON, object ordering, progress storage, and the recovered Bullet collision hulls remain unchanged. Detailed surface decorations do not add physics bodies. Hulls remain gameplay approximations; replacing a visual model does not automatically rebuild its collision shape. Break-up fragments retain their existing trajectories and geometry with themed textures.

Models range from approximately 800 triangles for a crate to 10,700 for a detailed powder keg. OBJ parts are reused across levels. These are mobile-oriented meshes, but sustained performance on the user's phone has not been measured.

## Regenerate authored assets

The generated OBJ and PNG assets are checked into this project and normal Android builds do not require Python imaging libraries. To regenerate them, use Python with Pillow and NumPy, and install the DejaVu Serif Bold font at the path referenced in the UI generator:

```sh
python3 tools/generate-pirate.py
python3 tools/generate-pirate-ui.py
```

The first command regenerates procedural meshes/textures, the cargo manifest, and fragment texture assignments. The second repacks the pirate UI into the existing startup atlas while preserving its original sprite region. Both commands replace generated assets, so export custom mesh edits separately before regenerating.

`assets/pirate/harbor.png` was created with the built-in imagegen tool using the supplied image as visual reference. It is stored in this project and is not regenerated by either script. The prompt asked for a full-bleed portrait sunset pirate harbor with blue ocean, a distant ship, palm-covered lighthouse island, timber pier, edge ropes and glowing lanterns, with the central cargo, cannon, UI, text and foreground obstacles removed so live 3D gameplay can occupy the center.

## Run and build

```sh
python3 web-editor/serve.py
cargo run --release --locked -- --portrait --level 13
./gradlew --offline --no-daemon :app:assembleDebug
```

The browser editor is at http://localhost:8050/. The normal APK is `app/build/outputs/apk/debug/app-debug.apk`, with application ID `org.smashland.rust` and launcher label **Pirate Smash**.

To test alongside an installation with a different signing key, use `-PsmashApplicationId=org.smashland.pirate.preview`. This produces a separate app with separate progress and materials. Run the normal Gradle command afterward to restore the normal APK output. A build signed with a different key cannot update an existing installation; retain the original signing key when shipping an update that preserves app data.

## Verification

- All 25 Rust tests pass with `cargo test --locked --offline`.
- The normal Gradle debug build contains both arm64-v8a and x86_64 libraries. The 52 pirate/level/UI asset files checked in the APK match their source files byte for byte.
- Chromium with Filament Web 1.70.0 passes GPU picking, editing/exporting/reimporting all 1,000 JSON stages, OBJ vertex editing/export/import, and a 390-pixel layout check. Unedited levels and mesh lines are preserved. The actual Rust loader accepts the browser-exported JSON.
- The Android x86_64 emulator renders the home screen, the 98-object level 13, and selected-object material controls. Firing a shot changes the counter from 20 to 19 and clears targets without a crash. The harbor uses separate emission scaling so its display-referred colors do not overexpose the native scene.
- Physical-phone GPU performance remains unmeasured.

## Harbor water and brass trim

The shared water shader layers moving wave slopes in world space, projects reflections into the harbor illustration, and uses Fresnel to increase reflection at grazing angles. The reflection source is the illustrated harbor, so it omits moving cargo. The browser editor remains an orbitable cargo and platform preview with the same updated brass finish.

Rebuild the water material with Filament 1.70.0's material compiler after editing the shared shader. The shoreline mask is generated from the harbor composition.

```sh
python3 tools/generate-water-mask.py
matc -p mobile -a opengl -o assets/filament/water.filamat native/filament/water.mat
```
